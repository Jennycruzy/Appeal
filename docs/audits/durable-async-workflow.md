# Durable asynchronous workflow audit

Recorded: 2026-08-31

The local runtime now has typed, reference-only wake handlers for
`appeal.evidence.arrived` and `payer.determination.received`. A handler
rehydrates the tenant-scoped case and reference-only workflow session, resolves
any evidence body through a server-side input resolver, and then re-runs the
deterministic Evidence Floor or payer boundary. Events cannot carry denial,
chart, prompt, or prose fields. The persisted session contains a one-way
patient-scope hash (scoped to tenant, case, and patient) and processed event
IDs; it never stores the raw patient ID. Evidence resumption fails closed when
an older capsule has no patient binding rather than accepting an unscoped chart
input.

The reproducible proof is
[`evidence/async-workflow-proof.json`](../../evidence/async-workflow-proof.json),
generated by `scripts/run_async_workflow_proof.py`. It records:

- a missing-evidence case rehydrated by a new runtime instance and resumed to
  `AWAITING_CLINICIAN` after an evidence event;
- a payer determination rehydrated after clinician approval and closed at
  `CLOSED_WON` with exactly one external mutation;
- a no-progress evidence retry recorded once and deduplicated by event ID;
- an expired case closed by the Deadline Sentinel tick; and
- a verified hash-chained receipt tip with no raw content persisted.

The case store and session store use expected fingerprints for updates. A
replayed event whose ID is already in the session is a duplicate; a stale event
for a case that has advanced is also a no-op. Pended payer decisions are
recorded as ignored without mutation, while malformed decision metadata is
rejected before any transition.

The six local board stories used for operational review are generated by
`make seed-demo-cases` and recorded without raw case content in
[`evidence/seeded-demo-tenant.json`](../../evidence/seeded-demo-tenant.json).

This closes the bounded local restart/replay behavior. It does not yet close
the hosted Gate 3 requirement: the current Cloud Run deployment still invokes
the managed Agent Runtime only for one allowlisted synthetic checkpoint, and a
fresh hosted Pub/Sub evidence/payer wake plus end-to-end trace must still be
captured after deployment.
